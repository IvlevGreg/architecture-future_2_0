# Обоснование конфигурации Terraform

| Параметр                           | Выбор ресурсов и параметров                                                                      | Причины использования декларативного подхода                             | Infrastructure as Code (IaC)                                              | Комментарий                                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------- |-------------------------------------------------------------------------------|
| Сеть (VPC) + подсеть               | Создана сеть `corp-network` и подсеть `domain-subnet` (например, 10.10.0.0/24) для одного домена | Мы описываем _что_ требуется (выделенная сеть, подсеть) без ручных шагов | Код версииуется, легко разворачивается для новых доменов                  | Изоляция домена (например, финтех, ИИ, медицина) → снижение риска пересечений |
| Виртуальная машина: 4 ядра / 16 ГБ | VM с 4 ядрами и 16 ГБ памяти — ориентир для аналитической нагрузки / витрины данных              | Декларативно задаём конфигурацию, Terraform сам подберёт операции        | Можно повторно развернуть с теми же ресурсами                             | Подходит для бизнес-аналитики, отчётов и портала самообслуживания             |
| Диск: network-ssd, 1 ТБ            | Диск типа `network-ssd`, объём 1024 ГБ                                                           | Большой объём настроен через код → удобно масштабировать                 | Инфраструктура как код позволяет сменить размер или тип без ручной работы | Для старта 1 ТБ, дальше масштабируемся                                        |
| NAT-интерфейс                      | NAT включён (`nat = true`), чтобы VM имела выход в интернет для обновлений и интеграций          | Конфигурация описана один раз — нет ручных настроек                      | Повторяемость: все домены получат одинаковую сетевую конфигурацию         | Важно для обеспечения доступа, при этом входящие порты можно ограничить       |
| Флаг `enable_real = false`         | Переменная-флаг переключает режим: песочница или реальное развёртывание                          | Код легко адаптируется: единственный флаг — и мы в тестовом режиме       | IaC делает среду воспроизводимой и безопасной для тестов                  | По умолчанию песочница → минимизирует риск затрат и случайных изменений       |
| Бэкенд `local`                     | Локальное хранение состояния (`terraform.tfstate`) для тестового режима                          | Можно сменить backend без переписывания конфигурации                     | Версия инфраструктуры под контролем, удобно для разработки                | При переходе к реальной среде заменим на удалённый backend (S3-совместимый)   |

## Как IaC способствует воспроизводимости и масштабируемости
- Конфигурации хранятся в системе контроля версий (Git и др.). Можно откатиться к предыдущей версии, аудитировать изменения. 
- Среды можно легко дублировать: тестовая, пред-прод, прод. 
- Масштабирование: для нового домена достаточно повторно использовать тот же шаблон инфраструктуры, изменив только параметры — код остаётся неизменным.
